recipe_fuz_app_env.ts

Recipes for a fuz_app server's .env.production content.

Every fuz_app server shares the same .env.production preamble — the NODE_ENV/PORT/HOST header, the Unix-socket DATABASE_URL, the cookie-signing key, and the bootstrap-token path — plus, behind a reverse proxy, the load-bearing trusted-proxies comment block. These build that shared content once so a config concatenates it with its app-specific vars instead of re-typing security-relevant prose that must converge:

  • fuz_app_env_base — the common header through FUZ_BOOTSTRAP_TOKEN_PATH.
  • fuz_app_trusted_proxies — the FUZ_<infix>_TRUSTED_PROXIES stanza (the comment explaining why a missing value collapses per-IP rate limits and ruins audit_log.ip), keyed by the service's env-var infix.

Templating boundary

fuz_app_env_base returns the whole zap template content, {type: 'template', template, vars, kinds}: the caller passes the values (port, cookie_keys) and its own lines (extra), and gives the result as the file's content. The header holds {{port}} / {{cookie_keys}} as placeholders, substituted at apply time, while eval-time values (user, service, config_dir) are interpolated here. A caller's lines (allowed origins, facts dirs, SMTP, …) bring their own variables and kinds; fuz_app_trusted_proxies returns text for them.

Quoting

The file has two readers: systemd reads it as an EnvironmentFile=, and OpenRC's init script reads it as data by a subset of those rules (see recipe_alpine_openrc.ts). So each value these interpolate or leave for the template engine is one single-quoted word (single_quote), which both read literally, \ included. systemd honours a quote only where it opens the value, so after the closing ' it reads quotes as text and \ as an escape ('\'' misreads), and it ends a value at a line break; the OpenRC reader refuses such a line. A value holding a ', a line break, or a NUL is refused at eval (ENV_FILE_VALUE), naming the field.

A template value substituted into '{{cookie_keys}}' is the template engine's text, not quoted again, since it resolves at apply time: a value holding a ' would end the quoting, so systemd would read a different value and OpenRC would refuse to start the service. So cookie_keys is an env_value, which zap refuses a ' (and a line break), and {{port}} a port, which holds no quote. The lines a caller appends are the caller's to quote, by the format recipe_alpine_openrc.ts documents, and the placeholders in them the caller's to give a kind.

Recipes are imported at config eval time inside zap's sandboxed config eval (fgro eval), which has no network, no writes, and no environment, and where the clock and randomness throw. This module is therefore a set of pure functions: each only assembles a string from its arguments — no I/O, no clock, no randomness, no imports beyond types and the pure single_quote and carries_reference. The output is deterministic for given inputs (stable ordering, trailing newline), so it stays a reliable content-addressed plan artifact.

(options: FuzAppEnvBaseOptions): TemplateContent import {fuz_app_env_base} from '@fuzdev/zap/recipe_fuz_app_env.js';

Build a fuz_app server's .env.production content: the shared header, then the caller's extra lines.

The header emits NODE_ENV/PORT/HOST, the DATABASE_URL over the PostgreSQL Unix socket in /run/postgresql (where Debian and Alpine both put it), SECRET_FUZ_COOKIE_KEYS, and FUZ_BOOTSTRAP_TOKEN_PATH — the section identical across fuz_app server deploys. {{port}} and {{cookie_keys}} are placeholders whose values are port and cookie_keys, held to port and env_value.

returns

TemplateContent

the template content: the header (ending in a newline) and extra's lines, the variables of both, and their kinds.

throws

  • Error - when `user`, `service`, or `config_dir` can't be written as they must be, `cookie_keys` carries no reference, or `extra` names a variable of the base's

Build the FUZ_<infix>_TRUSTED_PROXIES env stanza (comment + var line).

The comment is the load-bearing rationale: without the var, the backend attributes every request to 127.0.0.1 (nginx's loopback address), so per-IP rate limits collapse into one shared bucket and audit_log.ip is useless.

FuzAppEnvBaseOptions import type {FuzAppEnvBaseOptions} from '@fuzdev/zap/recipe_fuz_app_env.js';

Options for fuz_app_env_base.

user

The DB role in DATABASE_URL. The server connects over the Unix socket, where the stock peer rule admits only the OS account of the same name, so this is the account the service runs as. Letters, digits, _, ., and -, written out (no reference): it is a name in DATABASE_URL, refused at eval otherwise.

type string

service

The database name in DATABASE_URL. Letters, digits, _, ., and -, written out (no reference), refused at eval otherwise.

type string

config_dir

Directory holding secret_bootstrap_token, e.g. /home/<user>/.myapp. The emitted FUZ_BOOTSTRAP_TOKEN_PATH is <config_dir>/secret_bootstrap_token.

type string

port

The port the server listens on, {{port}}'s value (PORT). Held to port.

type string | number

cookie_keys

The cookie-signing keys, {{cookie_keys}}'s value (SECRET_FUZ_COOKIE_KEYS) — a reference, zap.env('SECRET_FUZ_COOKIE_KEYS'). Held to env_value: it sits inside single quotes. A value that carries no reference is refused: the keys would be written into the plan, the lock, and the last-run report, where a reference's value never is.

type string

extra?

The caller's own lines, appended after the base, with their variables.

type FuzAppEnvExtra

FuzAppEnvExtra
#

recipe_fuz_app_env.ts view source

FuzAppEnvExtra import type {FuzAppEnvExtra} from '@fuzdev/zap/recipe_fuz_app_env.js';

A caller's own env-file lines, appended to fuz_app_env_base's: their text, the values of the placeholders they add, and those values' kinds.

The lines may use the base's {{port}} and {{cookie_keys}}, but vars and kinds can't name them: the base's values and kinds are its own. Used whole, the content carries its kinds; overriding kinds or rebuilding the content drops them. A variable vars adds and kinds leaves out declares no kind (a reference in its value is still held to text; a value written out is substituted unchecked), so give each the kind of the place it lands (env_value inside single quotes).

template

The lines, quoted by the format recipe_alpine_openrc.ts documents.

type string

vars?

The values of the placeholders the lines add.

type Record<string, unknown> & { port?: undefined; cookie_keys?: undefined; }

kinds?

The kinds of the variables vars adds.

type Record<string, TemplateKind> & { port?: undefined; cookie_keys?: undefined; }
