zap.ts

The zap.ts authoring API — the builder a config's default export receives.

A @fuzdev/zap config is a module whose default export is a (zap, ctx) => void | Promise<void>: it calls the ZapBuilder methods to declare the target, resources, and deploy block. The builder collects those declarations into the JSON the Rust engine parses against crates/zap_types/src/schema/ (mirrored by schema.ts); the builder shim injects each resource's type discriminant, so authors never write type.

The builder's types live here; the payload types it takes live in schema.ts, each imported from its own module:

import type {ZapBuilder} from '@fuzdev/zap/zap.ts'; import type {FileResource} from '@fuzdev/zap/schema.ts';

env

A reference to the operator environment variable name: the value is read from the environment of the machine zap runs on, when the field holding the reference is used — never while the config is evaluated, which has no environment.

The result is a string to place in a field that takes a reference — whole (host: zap.env('DEPLOY_HOST')), interpolated into a template literal, or concatenated (path: '/srv/' + zap.env('APP') + '/data'). It is opaque: it holds a marker, not the value, so slicing, splitting, case-changing, or encoding it leaves something that is no longer a reference: the config fails to evaluate when part of the marker survives, and otherwise the result is ordinary text. A field that takes no reference rejects one, naming the field. A recipe, which has no builder, calls env_ref from @fuzdev/zap/env_ref.ts for the same string.

mask

Declare env-var names secret: ones zap doesn't recognize by where they are used, their name, or the form of their value. Each is a variable's name — 'LICENSE_CODE', not zap.env('LICENSE_CODE') — and POSIX ([A-Za-z_][A-Za-z0-9_]*); anything else throws when called.

unmask

Declare env-var names not secret, where zap reads one as a secret by its name or the form of its value and it isn't. Each is a variable's name, POSIX ([A-Za-z_][A-Za-z0-9_]*); anything else throws when called. Unmasking a variable the config uses as a fetch credential (auth) is rejected when the config is read.

ZapConfigModule import type {ZapConfigModule} from '@fuzdev/zap/zap.js';

The default-export signature of a zap.ts config — a pure (zap, ctx) function with no ambient authority. It may be async: zap waits for the promise, and a builder call made after it settles fails the evaluation, even when the config catches the error (a guard against a forgotten await).

Plan-time inputs to a config's default export. There are none, so it is empty: the same zap.ts always evals to the same declared state (the changeset built from it then depends on what detection finds on the target).
