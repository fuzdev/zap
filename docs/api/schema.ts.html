schema.ts

The zap.ts authoring schema — TypeScript types that mirror the Rust serde JSON boundary in crates/zap_types/src/schema/ (the authoritative source).

These give a config author full type-checking against the same contract the Rust engine parses: every resource payload, the nested content/source unions, the closed-set enums, and the deploy() block. The Rust structs carry #[serde(deny_unknown_fields)], so these interfaces have no index signatures — a misspelled field is a type error here exactly as it is a parse error in the engine.

Scalar newtypes on the Rust side (Mode / ContentHash / AccountName / ResourceId / EnvVarName) serialize as plain string; they are typed as string here with their format invariant noted, since TypeScript can't express the runtime validation the engine applies at parse.

A field is optional (?) here exactly when the Rust field is Option<T> or carries #[serde(default)]. The dual-gated kitchen-sink fixture (src/test/fixtures/kitchen_sink_config.ts — type-checked against these types, then eval'd and parsed by the Rust config_conformance test) guards this module and the Rust schema from drifting.

type "template"

template

The template body, used as declared. It takes no reference. A placeholder is a variable's name between {{ and }} and nothing else; one that names no variable is rejected by the structural gate.

type string

vars?

Variable values substituted for {{key}}, in one pass: a value is never read for placeholders. A string value may be or carry a reference, resolved before it is substituted. A value that isn't a string is substituted as its compact JSON text and takes no reference at any depth. A variable no placeholder names is rejected by the structural gate. A reference whose value holds a line break (CR or LF) or a NUL holds the file and refuses its write: it would add a line.

type Record<string, unknown>

kinds?

The kind of value each named variable must render to (TemplateKind). Each key names a variable in vars, or the structural gate rejects it. A declared kind is checked on a value written out when the config is read, and on one carrying a reference once it resolves, which holds the file and refuses its write when it isn't its kind. A variable not named here declares no kind: a reference in its value is still held to 'text' once it resolves, and a value written out is substituted unchecked.

type Record<string, TemplateKind>

TemplateKind

type "text" | "hostname" | "port" | "path" | "email" | "env_value"

import type {TemplateKind} from '@fuzdev/zap/schema.js';

The kind of value a template variable renders to, checked on its whole rendered value. Mirrors the Rust TemplateKind.

  • text — any one line: no line break, NUL, or reference delimiter. Every kind keeps this rule. A reference's value is held to it whether or not its variable declares a kind; a value written out is held to it only when its variable declares one.
  • hostname — a DNS host name (RFC 1123): dot-separated labels of ASCII letters, digits, and -, each 1 to 63 bytes, no leading or trailing -, at most 253 bytes, with no trailing dot, no wildcard, and no _.
  • port — a decimal number from 1 to 65535, with no sign or leading zero.
  • path — an absolute path whose names are ASCII letters, digits, ., _, -, +, and @, with no empty, ., or .. name.
  • email — a local part of ASCII letters, digits, ., _, %, +, and - (no leading, trailing, or doubled .), an @, and a hostname.
  • env_value — a value written inside single quotes in an env file: text with no ', which would end the quoting.

None of the hostname, port, path, or email alphabets holds a character a config grammar reads as structure (;, {, }, a quote, a blank), which is what a kind is for: a {{domain}} in an nginx server_name declared hostname can't end the directive.

UserResource import type {UserResource} from '@fuzdev/zap/schema.js';

user resource payload — a Unix user (shell, home mode, SSH keys, sudoers).

username

Unix username to create/manage. Mirrors AccountName — a portable Unix name ([a-z_][a-z0-9_-]*, optional trailing $; anything else is rejected at parse). zap manages the user's home as /home/<username>, so 'root' (home /root) is rejected by the structural gate, and an existing account whose /etc/passwd home is anything else is held at detection when home_mode or ssh_keys is declared. With either declared, a /home/<username> directory root owns is given to the user when zap creates the account, and left as it is for an existing one; one another uid owns, a link, or a non-directory there holds the user.

type string

shell?

Login shell (e.g. /bin/bash); system default when absent. It takes no reference (rejected when the config is read): detection reads it as declared.

type string

home_mode?

Home-directory mode (e.g. "711"). Mirrors Mode — octal, 7777 at most.

type string

ssh_keys?

SSH key configuration, if managed.

type SshKeys

sudo?

Sudo access: a grant, or false to remove. Absent = unmanaged.

type UserSudo

groups?

Supplementary groups the user must belong to (additive — listed groups are added, never removed). Mirrors AccountName[] — portable Unix names (see AccountName). Absent/empty = unmanaged.

type string[]
